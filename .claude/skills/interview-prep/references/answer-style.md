# Как писать вопросы и ответы

## Формат HTML (иначе раздел не загрузится)

- Раздел — один `<section>`; первым идёт `<h1 id="NN-slug">NN. Название</h1>`. Номер раздела общий для публичного и личного файла.
- Группа — `<h2>Название</h2>`.
- Вопрос — ровно так:
  `<h3 id="qNN.M"><a class="anchor" href="#qNN.M">#</a>NN.M Название 🔥</h3>`.
  Номера идут подряд с 1. В конце заголовка обязательна метка: 🔥 — спрашивают почти всегда, ⭐ — часто, 🎓 — для senior или «со звёздочкой».
- Ответ — весь HTML до следующего `h2`/`h3`. Между вопросами ставится `<hr />`.
- Ссылки на готовые ответы: `<a href="#q9.14">9.14</a>`, на раздел — `<a href="#09-databases">9</a>`. Id разделов выводит `list-questions.mjs`.
- Код: `<pre><code class="language-csharp">…</code></pre>`. Внутри экранируются `&lt;`, `&gt;`, `&amp;`, в том числе в generics: `List&lt;T&gt;`.

## Содержание

- Язык — русский. Термины и идентификаторы — как в оригинале (consumer group, `IOptions`).
- Ответ строится так, как его произносят на интервью: сначала определение или вывод в 1–2 фразы, потом детали. Таблица, когда сравниваются варианты. Код, когда без него непонятно. Подвох или типичная ошибка — отдельно.
- Ответ привязан к стеку и домену вакансии: примеры из её предметной области, сравнение с .NET для смежных технологий.
- Не повторять то, что уже есть в базе: дать ссылку на готовый вопрос и дописать только новое.
- Версии и «что нового» — только после проверки по свежим источникам (поиск в интернете). Если не уверены — так и написать и посоветовать сверить по официальной документации.
- Внутреннее устройство компании (домен, команда, процессы) — пометка *«Предположения по открытой информации — уточните на интервью»*.
- Где уместно — подсказка «как отвечать», «пример ответа» или «подготовьте свою историю по STAR».
- Длина — как в базе: обычно 1–4 экрана. Без воды, без вступлений «это важный вопрос».

## Что куда

| Содержимое | Куда |
|---|---|
| Всё, что связано с компанией: описание, карта, домен, её связка стека, вопросы к ней, истории из опыта пользователя | Личный файл `content/private/answers.private.html` (вне git) |
| Общая тема, которой не хватает базе (новая технология, целый пласт вроде фронтенда) | Публичный `content/answers.html` — только с согласия пользователя. Это меняет `RealContentTests` (список разделов и число вопросов) и попадает на GitHub |

В публичный файл нельзя писать названия компаний, вакансии, личные данные и истории пользователя.
